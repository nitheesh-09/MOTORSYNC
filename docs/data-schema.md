## 2. ESP32 Raw Transducer Payload Schema

Dedicated real-time schema for direct hardware ingestion (`POST /api/v1/telemetry/raw`):

```json
{
  "motorId": "MTR-001",
  "timestamp": 1727700000000,
  "voltage": 11.92,
  "current": 1.42,
  "temperature": 37.8,
  "vibration_x": 0.31,
  "vibration_y": 0.18,
  "vibration_z": 0.92
}
```

### 3-Axis Vibration Representation

The vibration transducer outputs 3 physical axes:
- `vibrationX`
- `vibrationY`
- `vibrationZ`

These axes are preserved unadulterated in `raw_telemetry` and analyzed individually (RMS, Peak, Peak-to-Peak, Kurtosis, Crest Factor).
The composite magnitude is calculated dynamically:
$$\text{magnitude} = \sqrt{\text{vibrationX}^2 + \text{vibrationY}^2 + \text{vibrationZ}^2}$$
Magnitude is explicitly flagged as a calculated quantity.

## 3. Three-Tier Data Provenance

MOTORSYNC maintains clear separation of origin for every data point:

1. **PHYSICAL TRANSDUCERS (4 Channels / 6 Signals)**:
   - Acquired directly by hardware sensors on the motor:
     - Voltage (PT Potential Transformer / Voltage Divider)
     - Current (CT Current Transformer / Shunt)
     - Temperature (RTD / Thermocouple / DS18B20)
     - 3-Axis Vibration (X, Y, Z Accelerometer)
   - Provenance tag: `PHYSICAL_MEASUREMENT` / `ESP32_HARDWARE`

2. **EXTERNALLY EXTRACTED FEATURES**:
   - Calculated upstream on the External Data Acquisition Laptop before transmission:
     - RMS, Peak, Crest Factor, Kurtosis, Skewness
     - Active Power ($P = \sqrt{3} \times V \times I \times 0.85 \text{ kW}$)
     - Temperature Rise Rate ($\Delta T / \Delta t$)
     - Dominant Frequency & Band Energy
   - Provenance tag: `EXTERNAL_PROCESSING`

3. **MOTORSYNC PLATFORM ANALYSIS**:
   - Computed centrally by MOTORSYNC:
     - Derived RPM ($RPM = f_{1X} \times 60$)
     - Multi-signal Health State (`HEALTHY`, `WARNING`, `FAULT`)
     - AI Diagnostic Assessment & Affected Section
     - Commissioning Baseline Deviations ($\Delta T, \Delta\text{Vib}, \Delta I$)
   - Provenance tag: `MOTORSYNC_CALCULATION`

## 4. Allowed Source Types

- `SYNTHETIC`: Generated by internal development simulation harness or test scripts.
- `ESP32`: Real-time raw sensor time-series streamed directly from ESP32 hardware.
- `EXTERNAL_LAPTOP`: Transmitted by external acquisition laptop.
- `OFFLINE_FILE`: Imported from uploaded CSV, JSON, or XML recording.
- `HARDWARE_GATEWAY`: Reserved for future direct industrial gateway connection.
